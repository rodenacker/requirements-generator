# write-reingestion-extract.md

**Purpose:** Turn an accepted `/analyse-inputs` artefact into a **re-ingestion extract** — a compact Markdown projection of the analyser's final in-memory model — and write it into `documentation/` so that `/requirements` and `/generate-prd` read the analysis as an ordinary `Native-text` input. Replaces copying the whole HTML artefact into `documentation/`: that HTML is read raw (CSS, SVG, Mermaid source and escaped JSON included), which floods the drafter's context and breaks byte-exact quoting. The extract carries only the analysis content, unescaped, with the analysis's own `[SRC: <filename>]` markers kept verbatim.

This skill is the sole writer of `documentation/*.analysis.md`. Its overwrite rule is `IS-05` in `framework/shared/input-safety.md`.

**Inputs:**
- `method_name` — the registry `name` of the methodology (a kebab slug, e.g. `glossary`, `jtbd`, `swim-lane-process-mapping`).
- `method_title` — the human title used in the extract's H1 (e.g. `Glossary`, `Jobs-To-Be-Done`).
- `artefact_path` — repo-relative path of the accepted HTML artefact (the registry `output_path`).
- `model` — the analyser's final in-memory model, after every Revise has been applied. For a method with a JSON or YAML body block it is the object serialised into that block; for a method with no body block it is the object its reference asset defines under `## Re-ingestion extract model`.
- `run_count` — the artefact's run number.
- `manifest_fingerprint` — the SHA-256 of `generated-docs/requirements/source-manifest.json` the run was built on.
- `omit_keys` (optional) — extra top-level or nested keys the caller drops from the body (rule R1).

**Paths (derived, never passed):**
- `target_path` = `documentation/<method_name>.analysis.md`.
- `staged_path` = `<dirname(artefact_path)>/<method_name>.analysis.md` — the copy the guard compares against (e.g. `generated-docs/analyse-inputs/GLOSSARY/glossary.analysis.md`).

The `*.analysis.md` suffix mirrors the `*.converted.md` precedent: the class is recognisable by filename pattern alone.

**Outputs:** exactly one of:
- `written` — both files written and verified; the target now equals the staged copy.
- `kept` — the consultant chose to keep their own `target_path`; nothing was written.
- `self-check failed: <reason>` — the rendered string broke a step-2 check; nothing was written. The caller surfaces the reason and fails its handback (a content defect in the caller's model, not a write failure).
- `RF-04 trigger` — a write failed verification; the caller halts per `framework/shared/refusal-registry.md > RF-04 artifact_write_unverified`.

**Used by:** every `/analyse-inputs` analyser under `framework/agents/analyses-inputs/`, at its handback gate's `Accept & use` branch. `/analyse-requirement` does **not** use it: a requirement analysis cites a derivative of `requirements.md`, so feeding it back into `documentation/` is circular.

## Procedure

Walk in order. A failure at any step returns immediately; later steps do not run.

1. **Render** the extract as one in-memory string:

    ```
    # <method_title> — re-ingestion extract

    > Generated by `/analyse-inputs` (`<method_name>`) from `<artefact_path>`, run #<run_count>, <ISO-8601 UTC date>, manifest `<first 12 of manifest_fingerprint>`. Derived view, not a raw input: its SRC citations name the original inputs that ground each line.

    <body>
    ```

    The header line is fixed text: it deliberately contains no angle brackets and no square-bracketed marker, so it passes the step-2 self-check. The `<body>` is rendered from `model` by these fixed, mechanical rules — no judgement, no summarising, no reordering beyond what they state:

    - **R1 — Omit bookkeeping.** Drop the keys `schema_version`, `manifest_sha256`, `manifest_fingerprint`, `generated_at`, `run_count`, `title`, `target`, any key ending `_count`, and any key in `omit_keys`. Also drop the run diagnostics `source_roster`, `irrelevant_to_domain_rows`, `quality_gates` and `discard_log` at any level: they list the manifest rows a run read or skipped, including this method's own extract, and R8 would otherwise turn every roster `filename` into an `[SRC: …]` citation.
    - **R2 — Top-level sections.** Each remaining top-level key becomes `## <key>`, with underscores turned into spaces and the first letter capitalised (`synonym_clusters` → `## Synonym clusters`). Keys keep the model's order. A top-level scalar renders as one plain paragraph under its heading.
    - **R3 — Arrays of objects.** An item that carries an `id` or a label key (`name` / `title` / `label` / `statement` / `term`) is an **entity**: it becomes a heading one level below its parent (`###` under a `##`, `####` under a `###`), capped at `######`; below that cap it renders as an anonymous record. The heading label is the `id` and the first present label value, joined by ` — `; with only one of the two, that one alone. A key used in the heading is not repeated as a field bullet. An item with neither is an **anonymous record**: under `- **<key>:**`, each one renders as an indented `- Item <N>` (1-based) bullet with its fields indented one level below it.
    - **R4 — Fields.** Keys render with underscores turned into spaces. A scalar field becomes `- **<key>:** <value>`. An array of scalars becomes `- **<key>:** v1; v2; v3`. A nested object becomes `- **<key>:**` with its own fields as indented bullets.
    - **R5 — Strings verbatim.** Emit every string exactly as it is in `model`: no JSON escaping (`\"`, `\n`, `é`), no HTML escaping (`&amp;`, `&lt;`), no truncation, no re-wording. A multi-line string becomes an indented block under its bullet, one source line per output line. This is what lets a drafter's `source_quote` match the extract byte-for-byte (`framework/skills/grounding-verifier.md`).
    - **R6 — Omit empties.** Drop `null`, empty-string and empty-array values, and a heading whose subtree is then empty.
    - **R7 — Plain Markdown only.** No HTML tags, no Mermaid, no SVG, no code fences. Provenance markers already in the values (`[SRC: <filename>]`, `[AI-SUGGESTED: AI-NNN | …]`) stay verbatim.
    - **R8 — Provenance fields render as their markers.** Many models store provenance as bare fields, which the HTML artefact renders as markers; the extract renders them the same way, so a drafter sees the markers the consultant saw. A value of a key named `filename`, `source_filename`, `source_filenames`, `sources`, `citations`, `src`, `anchor_src` or `anchor_source_filenames` (scalar or array of scalars) renders as `[SRC: <value>]` per value, unless it already starts with `[SRC:`. A key named `ai_id` renders as the AI marker, taking its blocking state from the first of: a sibling `blocking` (`true` → `[AI-SUGGESTED: <ai_id> | blocking]`, otherwise `… | non-blocking]`); else a sibling `marker` that starts with `[AI-SUGGESTED:`, carried verbatim; else neither is known, and the ID renders bare (`- **ai id:** AI-NNN`) rather than with an invented blocking state. The siblings `blocking` and `marker` are then not rendered. No other marker is ever produced.

2. **Self-check** the rendered string. Each failure returns `self-check failed: <reason>`:
    - no literal `{{` anywhere;
    - no match, case-insensitive and within one line, for `</?(?:pre|code|div|span|section|article|header|footer|nav|main|figure|svg|path|g|script|style|table|thead|tbody|tr|th|td|ul|ol|li|p|br|details|summary|h[1-6]|a|strong|em)\b[^>\n]*>` — an HTML tag leaked in. Only real tag names count: a quote's own angle-bracket text (`Dear <FirstName>`, `<PO number>`, `<5 days`) is content that R5 carries verbatim;
    - no `[SRC: <x>.analysis.md]` — an extract never cites an extract, its own or another method's;
    - at least one line beginning `## `;
    - every `[SRC: <x>]` and every `[AI-SUGGESTED: <x>]` substring also occurs in the file at `artefact_path`, read with its HTML entities decoded (`&amp;` `&lt;` `&gt;` `&quot;` `&#39;`). A marker missing from the accepted artefact means `model` is not the model that was rendered and accepted — for example a Revise applied to one but not the other.

3. **Guard (`IS-05`).** If `target_path` does not exist, go to step 4. If it exists:
    - If `staged_path` exists, compute the SHA-256 of both files' bytes (PowerShell `Get-FileHash -Algorithm SHA256`, or POSIX `sha256sum`). Equal → the target is still exactly what this pipeline last wrote; go to step 4 without asking.
    - Otherwise — `staged_path` is missing, or the hashes differ — the target was hand-edited, or was not written by this pipeline. Ask with `AskUserQuestion`:
        - Header: `Extract`
        - Question: *"`documentation/<method_name>.analysis.md` was edited since it was last written (or wasn't written by this pipeline). Replace it with the new extract?"*
        - multiSelect: false
        - Options: `Keep mine (Recommended)` — leave both files exactly as they are; `Replace` — overwrite it with the new extract.
    - `Keep mine` → return `kept`. Write nothing — not even the staged copy, so the next run still sees the difference and asks again.
    - `Replace` → go to step 4.

4. **Write and verify.** Compute the SHA-256 of the rendered string.
    - When a file at `staged_path` or `target_path` already exists, Read it first: the `Write` tool refuses to overwrite a file that has not been read in this session.
    - `Write staged_path`, then invoke `framework/skills/verify-artifact-write.md` with `path = staged_path`, that SHA-256, `expected_min_bytes = 256`.
    - `Write target_path` with the same string, then invoke `verify-artifact-write.md` the same way with `path = target_path`.
    - Either verification returning `RF-04 trigger` → return `RF-04 trigger`. Both `pass` → return `written`.

    The staged copy is written first so that an interrupted run can never leave a target whose twin is missing — a missing twin makes the next run ask, which is the safe direction.

## Extract rows in /analyse-inputs

Every `/analyse-inputs` analyser applies this rule in its manifest-read step, before tier dispatch:

- A manifest row whose `filename` matches `*.analysis.md` is a re-ingestion extract. Do not read it. Capture `(filename, reason: "re-ingestion extract (derived, not a raw input)")` to `skipped_rows`, so it appears in the artefact's skipped roster, and never cite it.

An input analysis analyses raw inputs. Without this rule an analyser would re-analyse its own (or a sibling's) extract and cite `[SRC: jtbd.analysis.md]` — a derived view presented as evidence. `/requirements`, `/generate-prd` and `/review-inputs` do **not** apply it: for them the extract is an ordinary input.

## Stale extract on plain Accept

When the consultant chooses plain `Accept` (not `Accept & use`) and `documentation/<method_name>.analysis.md` exists, the analyser adds one line to its handback, verbatim apart from the filled placeholder:

> *"Note: `documentation/<method_name>.analysis.md` is from an earlier run and does not reflect this one. Choose **Accept & use** next time to refresh it."*

Plain `Accept` writes nothing; the line only makes a stale extract visible.

## Self-validation

- `target_path` and `staged_path` were derived from `method_name` and `artefact_path`, never passed in or invented.
- The step-2 self-check ran on the exact string that was written, and passed.
- On `written`: both files exist, both verifications returned `pass`, and their SHA-256 values are equal.
- On `kept`: neither file was written in this invocation.
- The guard asked **only** when the target existed and was not byte-identical to the staged copy. No target, or an identical one, never prompts.

## Anti-Patterns

- **Do not cut the JSON or YAML body out of the HTML artefact.** It is HTML-escaped and JSON-escaped, so quotes in it no longer match their sources byte-for-byte, and two methods have no body block at all. Render from `model`.
- **Do not summarise, paraphrase or truncate.** The extract is a mechanical projection; R1–R8 are the only transformations. A shortened quote fails the drafter's grounding check.
- **Do not overwrite a target that differs from the staged copy without asking.** A hand-edited extract is consultant work (`IS-01`, `IS-05`).
- **Do not ask when the outcome is determined.** No target, or a byte-identical one, is written silently.
- **Do not delete an extract**, on any branch. The consultant removes extracts manually (`IS-03`).
- **Do not invent provenance markers.** The extract carries the analysis's existing `[SRC: <filename>]` and `[AI-SUGGESTED]` markers — verbatim, or rendered from their bare fields by R8 — and nothing else. It mints no new marker, ID or citation; the step-2 self-check enforces this.
- **Do not write anywhere else.** The skill's only writes are `staged_path` and `target_path`.
