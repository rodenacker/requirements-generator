# step-02-read-spec

**Goal:** Build the render plan + the disjoint component-ownership map (the collision-safety contract).

1. From the spec's **front-matter** read `device_targets` (`{ primary, breakpoints, touch }`) into the render plan verbatim — it is passed to every sub-agent at step-04 and drives the responsive contract (`visual-craft-standard.md §11`) plus, at step-06, which Playwright projects the gate runs. **Do not infer it** from the posture, the surface mix, or the absence of the key: a spec that predates the field (`device_targets` absent) is treated as `{ primary: "desktop", breakpoints: ["desktop"], touch: false }`, which is the historical behaviour, and that default is recorded in the handback so it is visible rather than assumed.
   From spec **§5** read each surface's realization (`standalone-screen` / `inline-drawer` / `inline-expand` / `modal` / `wizard-split`) + host/rendered-on for folds. From **§7** read the component inventory (per surface: components composed, reuse vs new, atomic tier). From **§8** read per-surface data binding (Property → fixture field → store). From **§3** read the Application character rows + copy-guidance sub-table into in-memory `app_character` (`null` on the `none recorded` fallback) — the copy-voice input for every surface's user-facing copy. From **§9** read the **Component minimum-feature contracts** table (per surface: families composed + applicable C-items) and the **Exceptions** table (per surface: `{item, reason}`) into the render plan as `component_contracts` / `contract_exceptions` — step-04 passes both per surface, step-07 checks the pagination item spec↔code, and step-06's gate omits a waived assertion. An **absent** contracts table is treated as "derive from §7" (project the families from each surface's inventory row) and recorded in the handback so the gap is visible; an absent or empty Exceptions table means **no waivers**, which is the expected state. An Exceptions row with an empty `Reason` is a **FAIL** here — do not carry it forward as a waiver.
1b. **Resolve role visibility (the only role source).** Read `requirements/requirements.md` §6.5 Access control (RBAC) and §3 personas. This is the **single** authority for role→operation grants in this pipeline: the design spec has no §6.5 and the blueprint's surface-inventory table has no Roles column, so before this step existed the instruction "per spec §6.5" resolved to nothing and each agent invented its own grant table (a real run shipped two — a `lib/nav.ts` role map and a `user-store.pagesForRole`, each able to disagree with the other).

   **Apply the transient `## Amendments (pending re-merge)` section first.** When `requirements.md` carries that section, its `AMD-NN` entries **supersede** the base §6.5 text they name; read the superseded values, not the originals (`docs/maintenance.md > New consumer of the transient section`; precedent: `blueprint-architect/steps/step-02-read-inputs.md`, `export-application-exporter.md`). Skipping this is not a cosmetic omission — `blueprint-architect` already honours amendments, so an amended RBAC cell would be reflected in the blueprint and ignored in the prototype: two disagreeing grant tables again, one layer up. **Read-only** — never write the section (it is owned exclusively by `framework/skills/apply-amendments-section.md`).

   **Derivation (mechanical — not a judgement call).** For each surface in the render plan:
   - **Visible roles** = every §6.5 role granted **at least `R`** on **any** entity the surface binds (surface→entity comes from spec §8, already read at rule 1).
   - **Withheld actions** per visible role = the `C`/`U`/`D` operations that role lacks on those entities — the input to the per-surface `role_visibility` the dispatch passes each sub-agent.
   - **Empty result → every role, not no roles.** A surface that binds no entity (spec §8 `none` — a navigation hub, a confirmation, a pure-UI screen) or whose entities appear in no §6.5 row yields an empty grant intersection. Treat that as **unrestricted**: record the **full role set, enumerated** — not an `all` sentinel, not `[]` — with a one-line note of why. Enumerating here rather than downstream keeps one representation end-to-end (`shared-component-conventions.md §6a`: `roles` is always a plain expanded list, so every consumer is just `roles.includes(activeRole)`). The opposite reading is a trap: an empty set read as "no roles" silently deletes the surface from every role's navigation, and the resulting app looks deliberately sparse rather than broken.
   - Record the prototype-wide **role set** (§3 personas in scope) alongside the per-surface map. The role *set* is what the chrome's switcher lists (PI-05); the per-surface map is what gates nav entries and in-surface actions.

   `role_visibility` stays `null` for a single-role prototype — the existing dispatch contract (`step-04`) is unchanged.

2. **Reuse-scan** the existing `prototypes/src/components/**` library: for every "new" component in §7, check whether an existing shared component already fits; if so, downgrade it to **reuse** (the library grows monotonically — rule 13).
2b. **Widen-scan (device-target coverage).** For every component marked `reuse`, compare the breakpoint coverage it carries against this prototype's narrowest `device_targets.breakpoints` entry. A component with no `md:`/`lg:` utilities (authored for a desktop-only prototype) reused by a prototype that lists `tablet` or `mobile` is upgraded from `reuse` to **`widen`**: it joins the owning sub-agent's `owned_files` with an explicit widen instruction (`shared-component-conventions.md §3` rule 6 — additive breakpoint classes only, desktop rendering unchanged, never a `*Mobile` fork). Assign each widened path to exactly **one** sub-agent so the partition in rule 5 stays disjoint. When `breakpoints == ["desktop"]` this scan is a no-op — nothing to widen.
3. **Cross-cutting data needs:** collect the set of entities across §8 (each needs a type + fixture + store). These are driver-owned (step-03).
4. **Route map + parallelizable classification** (decidable from the §5 realization — a closed enum, not a heuristic). Build `route_map`: per surface `{ route_path, realization, is_parallelizable }`:
   - `standalone-screen`, **non-primary** → `route_path = src/app/<name_slug>/<surface-kebab>/page.tsx`; `is_parallelizable = true` (its sub-agent authors this leaf route — see `step-sub-render-surface.md`).
   - the **primary/root** standalone surface → `route_path = src/app/<name_slug>/page.tsx`; `is_parallelizable = false` (the cross-surface hub; driver-owned in step-05).
   - `inline-drawer` / `inline-expand` / `modal` → **no own route** (rendered on the host's screen); `is_parallelizable = false` (driver composes onto the host route — many-to-one, the only collision risk, kept driver-owned).
   - `wizard-split` → N sub-step routes; `is_parallelizable = false` (driver-owned multi-step wiring).
5. **File-ownership map:** assign each genuinely-new shared component to exactly one owner:
   - a component used by exactly one surface → that surface's sub-agent owns its file;
   - a new component shared by ≥2 surfaces → the **driver** authors it in step-03 (before dispatch) so no two sub-agents race it.
   Then, for each `is_parallelizable` surface, **append its `route_map.route_path` to that surface's `owned_files`** — the sub-agent authors its own standalone leaf route alongside its components.
   Produce, per surface, a disjoint `owned_files: [<relative paths>]` list (uniquely-owned new components + any components assigned for `widen` at rule 2b + the one standalone route where applicable). **Verify the union is collision-free** — no path assigned twice; no route path collides with the driver-owned root `page.tsx`, a per-prototype `layout.tsx`, or any folded-host route; no *new* component path collides with an existing file. (A `widen` path deliberately names an existing file — it is the single sanctioned overwrite, and it is still owned by exactly one sub-agent, so disjointness is unaffected.) Route paths are unique by construction (one `<surface-kebab>/page.tsx` per surface), so the partition stays provably disjoint. A duplicate or collision is an `RF-04`-class self-validation FAIL — fix before dispatch.
6. Record the plan in memory (surfaces, realizations, `route_map`, per-surface owned_files, data-layer entities, reuse list, widen list, `device_targets`). No writes in this step.

Proceed to `step-03-ensure-fixtures-stores.md`.
