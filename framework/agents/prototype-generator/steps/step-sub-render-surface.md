# step-sub-render-surface (per-surface sub-agent)

**Role:** the instruction set for ONE parallel sub-agent dispatched by `step-04`. It renders the **new shared components** for exactly one surface and — when the surface is a **standalone secondary** screen — **authors that surface's own standalone route page**. It is the unit that makes generation parallel + safe.

**Activation:** load `framework/assets/persona-llm.md` + `framework/assets/characters/prototype-generator.md` (same stance as the driver).

**Assignment (passed in the dispatch prompt):** `{ surface_id, surface_intent, realization, host?, owned_files, owned_route_file (its own `src/app/<name_slug>/<surface-kebab>/page.tsx`, or null when the driver owns the route), route_map (outbound link target route strings + breadcrumb trail — knowledge only), nav_context (shared per-prototype `layout.tsx` present, or self-wire back-link/breadcrumb), components_to_reuse, data_bindings (Property→fixture-field→store), role_visibility (per-role visibility for this surface, or null — resolved by the driver at step-02 rule 1b from `requirements.md` §6.5; knowledge only, do not re-derive it), application_character (spec-§3 block: name + tone attributes + per-surface copy guidance, or null), posture, dimension_positions, ux_baseline_subset, visual_craft_subset, device_targets }`.

## Hard rules (collision-safety)

- **Write ONLY the files in `owned_files`.** These are new shared components under `src/components/{atoms,molecules,organisms,templates,domain}/` — plus, for a standalone secondary surface, your **one** `owned_route_file` (`src/app/<name_slug>/<surface-kebab>/page.tsx`).
- **Never** write any route file other than your own `owned_route_file`: not the root `page.tsx`, not a per-prototype `layout.tsx`, not a folded-host route, not a wizard route. Never write the data layer (`types`/`fixtures`/`stores`/`seed`) or any file not in `owned_files`. The driver owns those. (When `owned_route_file` is null you write no route at all — the driver composes your surface in step-05.)
- **Never overwrite** an existing component — reuse it (it's in `components_to_reuse`).
- Read the existing shared library + the shadcn `ui/` primitives freely.

## Render contract

0. **Timing (self-measure only).** Capture an ISO start timestamp at activation (`(Get-Date).ToUniversalTime().ToString('o')`) and an end timestamp immediately before returning; report them as `started`/`ended` in the manifest. **Do not append to `framework/state/timing.ndjson` yourself** — concurrent writes from parallel sub-agents would corrupt it; the driver emits your `render-surface` span from these values after the wave joins (see `prototype-generator.md > Timing log`).
1. Compose each owned component from shared `ui/` primitives + existing shared components, themed by the fixed brand tokens (no new palette/type/radius — D1).
1b. **If any owned component is an application shell** — i.e. it wraps a surface's content: `templates/AppShell*`, `templates/*Shell`, or anything else you author that renders `{children}` as a page region — it carries the **app-shell obligations** (colour-mode toggle + brand logo), unconditionally. The rule is canonical in `step-05-compose-route.md` rule 2 and applies identically to you: render `<ThemeToggle />` (imported from `@/components/atoms/ThemeToggle`, iff that file exists) inside the shell in an app-level header region you author if it has none — never as a caller-supplied prop, never gated on a declared catalogue slot. This is **not** the "shared intra-prototype nav" you are forbidden to author (rule 41): the nav enumerates routes and stays the driver's; these two are fixed app-level affordances of whatever shell you were assigned.
   **If your shell renders nav, consume the generated module — never derive it.** `import { NAV_BY_PROTOTYPE } from '@/data/nav'`, resolve by the first path segment of `usePathname()`, filter by `activeRole` (`entry.roles.includes(activeRole)`). The driver wrote it before this wave (`step-03` rule 4b); schema is canonical in `shared-component-conventions.md §6a`. Rule 41 forbids you from *authoring* shared nav — it never licensed inventing your own array instead, and a real run's shell did exactly that (a hand-rolled inline array on one page, competing with two other derivations elsewhere). Consuming the module is not authoring nav.
2. Apply the **posture + positions** to layout/density/disclosure/interaction only (e.g. dense table at D3+, inline-edit at D1+/P1, wizard step at P2, calm whitespace at P5). Realize the surface per its `realization`. For a **fold/wizard** surface (`owned_route_file` null) you produce only the component(s) the drawer/modal/expand/wizard-step needs — the driver wires them into the host/wizard route in step-05.
2b. **Visual-craft floor** (`visual_craft_subset`, canonical in `framework/assets/prototypes/visual-craft-standard.md`). This is a floor of the same standing as the baseline in rule 5 — a posture emphasises items, it never waives them. Concretely, on everything you author:
   - **Bind to tokens, never literals** (§1): `shadow-xs/sm/md/lg`, `text-xs…text-4xl`, `rounded-md/lg/xl`, Tailwind's 4/8 spacing steps, and a **bare `transition`** for timing (already brand-bound via `--default-transition-duration`/`--default-transition-timing-function`). For an explicit slower tier use `duration-[var(--duration-base)]`. **`duration-fast` is not a utility** — `--duration-*` is not a Tailwind namespace, so writing it emits no CSS and fails silently.
   - **Press must be felt** (§2): use a real semantic element (`<button>`, `<a>`, `<summary>`) so the template's global press layer reaches it; stamp **`data-pressable`** on any non-semantic clickable you author (clickable card, swatch, custom segment, footer row) and **`data-clickable`** on a clickable `<tr>` **of a row-like list that is not a data table**. Add `data-elevated` when the element rests on elevation. Do not author your own `active:` colour change: press is transform + elevation only, and any new fill composite would be a state whose on-colour `extract-brand-theme.md` never measured, which would make the both-modes contrast sweep assert against a non-existent state.
   - **A data-table row is never clickable** (`design-system-standards.md §1 > Tables`, canonical): no `onClick`, `data-clickable` or `data-pressable` on a `<tr>`/`<TableRow>` inside a `<table>` — the attribute does not redeem it, and step-07 fails the build on any hit. Make the row's primary identifier a **link/button in its own cell** and put row-scoped actions in a **dedicated action column**; the press response is then the cell control's, earned semantically.
   - **Hover must shift** (§3): one consistent shift per element — a fill from the measured list (`hover:bg-accent`, `hover:bg-muted/50`), or elevation +1 rung, or a 1px lift for navigating cards. Name the transitioned properties; never `transition-all`.
   - **Compose the shipped overlay primitives** (§4) — `ui/tooltip`, `ui/popover`, `ui/dropdown-menu`, `ui/dialog`, `ui/sheet`, `ui/select`. They already carry the fade + 4px lift + 2px-blur-clear entrance from `globals.css`. A hand-rolled overlay forfeits that entrance, the focus trap and `Esc`-to-close. **An icon-only control needs a tooltip** (and an accessible name).
   - **Type hierarchy + rhythm** (§6/§7): a real ramp (page title `text-2xl`/`3xl`, section `text-lg`/`xl`, body `text-sm`/`base`, meta `text-xs`), `tabular-nums` + right-align on numeric columns, one section gap for the whole surface (`space-y-6` default; tighter at dense D3, looser at calm), grouped-then-separated spacing. Uniform spacing everywhere destroys the grouping signal.
   - **Elevation ladder** (§5): never skip a rung on hover, never stack a heavy border on an elevated surface.
   - **Six states, not five** (§10): `active` and `loading` are the two this pipeline has historically dropped. Loading is visually distinct from disabled.
2c. **Responsive contract** (`device_targets`, canonical in `visual-craft-standard.md §11`). Design for the **narrowest** breakpoint in `device_targets.breakpoints` first, then widen with `md:`/`lg:`. Non-negotiable at every listed breakpoint: no horizontal page scroll; tables collapse to a card list rather than scrolling sideways (`GR-18`); sidebars become drawers below `md:`; multi-column forms become single-column below `md:`; dialogs become bottom sheets below `sm:` when `mobile` is listed; targets ≥44×44px when `touch: true` (so no `size="xs"` on a touch target), else the 24×24 baseline. A **desktop-only** target still must not overlap, clip or scroll horizontally when narrowed — reviewers open prototypes in half-width windows. Do not re-derive `device_targets` from the posture; use what you were given.
3. **Anti-fabrication:** every data-bound element binds to a Property in `data_bindings` (the blueprint closed set) and carries `data-prop="Entity.Field"` (or `F-NN:Param`). No invented fields. UI-only controls (search/sort/pagination/filters/save/cancel/density-toggle) are exempt and carry no `data-prop`. This applies to your components **and** to your route page (step 4).
4. **Author your own standalone route — only when `owned_route_file` is set.** Write that one `page.tsx`, composing your surface's components inside the shared chrome, and wire exactly what the driver wires for driver-owned routes (relocated here for your page):
   - store usage (`useXStore`) for data display + mutation (PI-02) — **gate every store read on `isLoaded`** per `shared-component-conventions.md §6` (`skipHydration: true` makes an unguarded read a hydration mismatch, hence a console error the per-route smoke fails on);
   - `activeRole` from the chrome store when `role_visibility` is non-null, varying visible components/actions per that rule (PI-05);
   - **`data-testid="primary-cta"` on the surface's primary action** (the verify-skill smoke contract — every route must expose it unless the surface genuinely has no primary action; do not omit it when one exists);
   - outbound navigation: `<Link href>` only to the **target route strings in `route_map`** (never guess a route) + this surface's breadcrumb. Rely on the shared per-prototype `layout.tsx` for sidebar/command-palette when `nav_context` says it exists — **do not author shared nav yourself**;
   - route metadata: set the route `<title>` to the prototype name;
   - re-assert anti-fabrication on the page (`data-prop` ∈ closed set), same as for components.
   The chrome already carries `data-testid="proto-chrome"` (from the app-level layout — do not re-stamp it).
5. **Baseline floor** (`ux_baseline_subset` from `ux-baseline-checklist.md`): render the three states (empty/loading/error) where the surface is a collection or async action; keyboard-operable + visible focus; name/role/value on controls; not-colour-alone for status; ≥24px targets. Self-check before writing.
5a. **Component minimum-feature contracts** (`component_contracts` in your payload; canonical `design-system-standards.md §1`, projected as C1–C10 in `ux-baseline-checklist.md`). Apply the contracts for the families you actually compose. The four most often dropped, because each is composition rather than styling and so is invisible when you look at one file:
   - **Pagination in every collection footer** — compose `molecules/Pagination` (wrapping the shipped `ui/pagination` primitive) with Next/Back, "Page N of M", the `5/10/20/50` page-size selector defaulting to `20`, and the total count. **Render it even when the fixture set fits on one page** — §1 requires consistency over cleverness, and a one-page table with no footer is the single most common form of this miss. Never hand-roll the nav out of bare buttons: the primitive carries the `role="navigation"` landmark the per-route smoke asserts.
   - **No whole-row click** — see rule 2b. Identifier as a link/button in its own cell; row actions in a dedicated action column.
   - **Sort state** — every data column sortable, with a visible indicator **and** `aria-sort` on the `<th>`, persisting across page changes.
   - **Tooltip on truncation** — a `truncate`/`line-clamp` cell carrying a data value composes `ui/tooltip` (or a `title`) with the full text. This is a self-check, not a grep: it is not mechanically detectable across multi-line JSX, so nothing downstream will catch it for you.
   Where your payload carries an `Exceptions` row for this surface, honour it as written and do not "fix" it into compliance.
5b. **Copy voice.** Phrase all user-facing copy you author — toast/notification text, error-state messages, validation messages, confirmation dialog bodies, empty-state explanations — in the `application_character` voice per its per-surface guidance (`null` → neutral professional). The character changes **tone only**: the three-state floor, plain-language/recovery requirements, entity-specific empty states, entity/field labels, and the closed data-binding set are untouched.
6. **No per-write verify.** Your writes (components + your one route page) are all compile-covered — `tsc --noEmit` + the Playwright smoke gate (`step-06`) catch a truncated or malformed write as a localized error the bounded-retry loop diagnoses by file path. Do **not** run `verify-artifact-write.md` on them (the option-08 compile-covered exception — see `CLAUDE.md > Constraints`). Self-check the render before returning instead.

## Return (route manifest)

`{ surface_id, files_written: [...], components_created: [...], components_reused: [...], components_widened: [...], props_bound: ["Entity.Field", ...], states_rendered: ["default","hover","active","loading","empty","error","disabled", ...], baseline_ok: true, craft_ok: true, started: "<iso>", ended: "<iso>" }`

- **`components_widened`** — components you were assigned as `reuse` but had to extend with additional breakpoint classes because this prototype's narrowest target is narrower than the coverage they carried (`shared-component-conventions.md §3` rule 6). Additive classes only, never a rewrite, never a fork. Empty array when none.
- **`craft_ok`** — your own confirmation that rules 2b/2c were applied, not merely read. Return `false` (or `failed`) rather than claiming a floor you did not meet; step-07's static sweep will catch it either way and the retry costs less than a shipped defect. — and, **when you authored a route**, also `{ route_written: "<owned_route_file>", primary_cta_present: true|false (false only if the surface has no primary action), outbound_links: ["<route_path>", ...] }`. Or `failed { surface_id, reason }` (e.g. a binding not in the closed set, an unrenderable realization, a `route_map` target you could not wire). The driver consumes the manifest in `step-05` (to skip re-authoring an already-written standalone route, or to compose a driver-owned one) and in `step-07` to self-validate.

## Anti-patterns

- Do not write outside `owned_files`; do not touch the data layer; do not write any route file other than your own `owned_route_file` (no root page, no `layout.tsx`, no folded-host or wizard route).
- Do not author shared intra-prototype nav (sidebar/command-palette/per-prototype layout) — inherit it from the driver-authored `layout.tsx`; only wire your own outbound `<Link>`s + breadcrumb.
- **Do not hand-roll a nav array, a `navItemsForRole()`-style helper, or a role→pages map, and do not create a `user`/`auth`/`session` store.** If your shell needs nav, import `NAV_BY_PROTOTYPE` from `@/data/nav` (rule 1b); roles come from `proto-chrome-store.activeRole`. Anything else is a second grant table, which is the defect this module exists to remove — and the data layer is driver-owned besides.
- **Do not write anything under `src/lib/`** — it is closed to the generator (`shared-component-conventions.md §4`); it is also not in your `owned_files`.
- Do not read a persisted store during render without an `isLoaded` guard (rule 4) — the per-route smoke fails the resulting hydration mismatch as a console error, and it will name *your* route.
- **Do not author a shell component without the colour-mode toggle** (and the brand logo when one was captured) when you own one — see rule 1b. "The shell has no header slot" is not a reason to omit it; author the region. Nor is "the driver will add it": the driver cannot write your `owned_files`.
- Do not guess a route string — wire `<Link href>` only to the targets given in `route_map`.
- Do not omit `data-testid="primary-cta"` when your surface has a primary action (the smoke gate fails the route without it).
- Do not invent data fields or fixtures; bind only to the closed set.
- Do not add a private/per-prototype theme or component folder (rules 15–16; D1). Binding to the brand's elevation, type and motion tokens is **not** adding a theme — those tokens already exist in `theme.css`; the prohibition is on inventing a competing one.
- Do not skip the three states or the baseline self-check.
- **Do not hardcode a craft literal** — no `duration-200`, `duration-[200ms]`, `shadow-[0_2px_8px_...]`, `text-[13px]`, `rounded-[10px]`, `ease-linear`, no raw hex, no Tailwind palette colour (`bg-green-100`, `text-red-900`). All of it comes from tokens (rule 2b). The palette-colour case is the one that has actually shipped: a real run's status badge used `border-green-300 bg-green-100 text-green-900`, invisible in dark mode, and passed every gate.
- **Do not write `duration-fast`/`duration-base`/`duration-slow` as class names.** They generate no CSS. Bare `transition`, or `duration-[var(--duration-base)]`.
- **Do not import `framer-motion` or animate with JS.** The contrast sweep silences CSS motion before measuring; JS motion survives it and makes the colour gate pass on a broken mode.
- **Do not use a text glyph or emoji as an icon** (`'✓'`, `'✕'`, `'ℹ'`, `'•'`). They ignore stroke weight, ignore the type ramp, and differ per platform. `lucide-react` with `currentColor`.
- **Do not leave a non-semantic clickable without `data-pressable`.** It looks fine and is silently untactile — the global press layer cannot match it.
- **Do not author zero breakpoints when `device_targets` lists more than `desktop`**, and do not substitute `overflow-x-auto` on a table for the `GR-18` card collapse. Sideways-scrolling tables are the single most common responsive failure in generated prototypes, and the one `GR-18` was written to stop.
- Do not let the `application_character` override the baseline floor, rename entities/fields/labels, or invent fields; and do not apply agent-character stances (your activation character) to product copy — the product speaks in the `application_character` voice, not yours.
- Do not return success with a fabricated binding or an unwired `route_map` target — return `failed` so the driver can route to retry/`RF-12`.
