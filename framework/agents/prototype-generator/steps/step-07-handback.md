# step-07-handback

**Goal:** Final self-validation + hand back to the orchestrator.

1. Run the driver self-validation (per `prototype-generator.md > Self-validation`):
   - every `LS-NN` realized (standalone route / folded-in-host / wizard steps); no surface missing;
   - every `data-prop` value ∈ the blueprint closed set (Grep the rendered routes/components vs the closed set); fixtures carry only closed-set fields — **zero fabrications**;
   - no component definitions under `src/app/<name_slug>/**`; no private per-prototype components; no existing shared component overwritten; new stores registered in `index.ts` + `seed.ts`;
   - **single-nav-table pass** — `src/data/nav/<name_slug>.ts` exists, the `src/data/nav/index.ts` barrel carries this `name_slug` **and** every earlier prototype's, every `NAV[].route` matches a route authored this run, every `roles` array is non-empty. Then Grep for a **second** derivation and for stray writes, in the same pass as the two greps above: a nav array literal / `navItemsForRole`-style helper / role→pages map outside `src/data/nav/`; any `user`/`auth`/`session` store; anything new under `src/lib/`; any unguarded persisted-store read (a `useXStore` read not gated on `isLoaded`). Any hit is a FAIL — four greps, one pass, per `shared-component-conventions.md §4/§6/§6a`;
   - `data-testid="proto-chrome"` (chrome) + `data-testid="primary-cta"` (primary action) present; multi-role surfaces read `activeRole` (PI-05);
   - **colour-mode toggle belt** — when `prototypes/.scaffold.json` has `colour_mode.strategy ∈ {toggle, custom}`, Grep `ThemeToggle` over the surface-wrapping components (this prototype's `src/app/<name_slug>/layout.tsx` if authored, plus every `src/components/templates/*` its routes compose) and require a hit in **every one of them** — not ≥1 across the set. A `≥1` predicate passes when one compliant shell sits beside four bare ones, which is precisely the shape a real run shipped; the obligation in `step-05-compose-route.md` rule 2 attaches to **each** component that wraps a surface's content, so the check must too. The only exemption remains a prototype composing no shell component at all (also rule 2). Run it alongside the closed-set `data-prop` grep above — same pass, two greps;
   - `ux-baseline-checklist.md` floor satisfied on every surface;
   - **visual-craft sweep** (`visual-craft-standard.md`) — one Grep pass over everything authored this run (`src/components/**` files in any manifest's `files_written`/`components_widened`, plus every route under `src/app/<name_slug>/**`). Each pattern below is a **FAIL** on any hit; these are mechanical, not judgement calls:
     | # | Pattern | Why it fails |
     |---|---|---|
     | 1 | `\b(?:bg\|text\|border\|ring\|from\|via\|to\|divide\|outline\|decoration\|shadow)-(?:white\|black\|slate\|gray\|zinc\|neutral\|stone\|red\|orange\|amber\|yellow\|lime\|green\|emerald\|teal\|cyan\|sky\|blue\|indigo\|violet\|purple\|fuchsia\|pink\|rose)(?:-\d{2,3})?\b` | Tailwind palette colours do not flip with the colour mode (`shared-component-conventions.md §4a`) |
     | 2 | `#[0-9a-fA-F]{3,8}\|rgb\(\|hsl\(` inside `className`/`style` | raw colour literal — same failure, different disguise |
     | 3 | `duration-\d\|duration-\[\d+m?s\]\|shadow-\[\|text-\[\d\|rounded-\[\d\|ease-linear` | hardcoded craft literal; timing/elevation/type/radius are tokens (`§1`) |
     | 4 | `duration-(?:fast\|base\|slow)\b` as a class name | emits **no CSS** — `--duration-*` is not a Tailwind namespace, so this fails silently. Correct: bare `transition`, or `duration-[var(--duration-base)]` |
     | 5 | `from ['"]framer-motion['"]` | JS motion survives the contrast sweep's transition kill, making that gate pass on a broken colour mode (`§9`) |
     | 6 | `['">](?:✓\|✔\|✕\|✗\|ℹ\|⚠\|●\|•)` as rendered content | text-glyph icon: ignores stroke weight and the type ramp, differs per platform. Use `lucide-react` |
     | 7 | `onClick` on a `div`/`span`/`li`/`tr` **without** `data-pressable` (or `data-clickable` on a `tr`) | the global press layer cannot match it, so the element is silently untactile (`§2`) |

     Pattern 1 is the one with a shipped precedent: a real run's `StatusBadge` used `border-green-300 bg-green-100 text-green-900` and its notice banner used red/green pairs — 15 hits total, past lint, typecheck, the per-route smoke **and** the both-modes contrast sweep, because that sweep only measures the states it happens to render. A grep catches what a renderer cannot.
   - **responsive coverage** — when `device_targets.breakpoints` is anything other than `["desktop"]`: at least one `sm:`/`md:`/`lg:` utility appears in **each** authored route and in **each** new layout-bearing component; no authored table uses `overflow-x-auto` as a substitute for the `GR-18` card collapse. Zero breakpoints across a run that declared a narrow target means the contract was read and not applied — the last real run authored zero breakpoints in every generated file. Also confirm each `components_widened` entry still typechecks and has no forked sibling (`*Mobile`, a markup-duplicating `variant`) beside it;
   - the verify gate returned `pass` / `pass-with-warning`.
2. Hand back to the orchestrator:
   - **`ok {name_slug, route, components_created[], components_reused[], components_widened[], device_targets, smoke_skipped?}`** — the orchestrator advances to the landing update (Step F4). `device_targets` is echoed because the landing-updater renders it as a badge on the prototype's card and records it in `.registry.json`; when it was defaulted (a spec predating the field), say so in the handback rather than presenting the default as a choice.
   - **`failed {structured}`** — a self-validation miss that bounded retry could not clear, or an `RF-12` halt. The orchestrator does not update the landing; the broken route + spec remain on disk for inspection.
3. Do not present to the consultant or run an accept loop — the orchestrator owns the Step-G accept gate.
