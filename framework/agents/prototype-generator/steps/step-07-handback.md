# step-07-handback

**Goal:** Final self-validation + hand back to the orchestrator.

1. Run the driver self-validation (per `prototype-generator.md > Self-validation`):
   - every `LS-NN` realized (standalone route / folded-in-host / wizard steps); no surface missing;
   - every `data-prop` value ∈ the blueprint closed set (Grep the rendered routes/components vs the closed set); fixtures carry only closed-set fields — **zero fabrications**;
   - no component definitions under `src/app/<name_slug>/**`; no private per-prototype components; no existing shared component overwritten; new stores registered in `index.ts` + `seed.ts`;
   - **single-nav-table pass** — `src/data/nav/<name_slug>.ts` exists, the `src/data/nav/index.ts` barrel carries this `name_slug` **and** every earlier prototype's, every `NAV[].route` matches a route authored this run, every `roles` array is non-empty. Then Grep for a **second** derivation and for stray writes, in the same pass as the two greps above: a nav array literal / `navItemsForRole`-style helper / role→pages map outside `src/data/nav/`; any `user`/`auth`/`session` store; anything new under `src/lib/`; any unguarded persisted-store read (a `useXStore` read not gated on `isLoaded`). Any hit is a FAIL — four greps, one pass, per `shared-component-conventions.md §4/§6/§6a`;
   - `data-testid="proto-chrome"` (chrome) + `data-testid="primary-cta"` (primary action) present; multi-role surfaces read `activeRole` (PI-05);
   - **colour-mode toggle belt** — when `prototypes/.scaffold.json` has `colour_mode.strategy ∈ {toggle, custom}`, Grep `ThemeToggle` over the surface-wrapping components (this prototype's `src/app/<name_slug>/layout.tsx` if authored, plus every `src/components/templates/*` its routes compose) and require a hit in **every one of them** — not ≥1 across the set. A `≥1` predicate passes when one compliant shell sits beside four bare ones, which is precisely the shape a real run shipped; the obligation in `step-05-compose-route.md` rule 2 attaches to **each** component that wraps a surface's content, so the check must too. The only exemption remains a prototype composing no shell component at all (also rule 2). Run it alongside the closed-set `data-prop` grep above — same pass, two greps;
   - `ux-baseline-checklist.md` floor satisfied on every surface;
   - **component-contract pass — pagination, checked spec↔code** (`design-system-standards.md §1 > Tables`; C2 in `ux-baseline-checklist.md`). Two-sided, the same shape as the closed-set `data-prop` and single-nav-table checks above:
     - **spec side:** every design-spec §7 inventory row whose `Shared components composed` cell names a collection-table organism (`RecordTable`, a `domain/<Entity>Table`, or anything composing `ui/table` as a data table) **also** names `Pagination`. A row that omits it is a FAIL — pagination is required, not a drafter judgement call (`shared-component-conventions.md §7.2`).
     - **code side:** every component authored this run that imports `ui/table` belongs to a surface whose §7 row names `Pagination`, **and** that component — or the organism it composes — imports `molecules/Pagination`. A `<table>` with no pagination anywhere in its own composition is a FAIL.

     **Why this is a spec↔code check and not a grep for `Pagination` in the route file.** §1 puts pagination in **the table's** footer, and `shared-component-conventions.md §7.2` puts `molecules/Pagination` inside `RecordTable` — so in the *correct* architecture the route file does not mention it, and a route-level grep would fail exactly the code that is right. "The same route subtree" is also an import walk, not something Grep decides. The design spec, by contrast, states per surface which pattern it is, which makes the predicate decidable and puts the obligation on the drafter where it belongs.

     A design-spec §9 `Exceptions` row naming this surface's pagination item, **with a reason**, downgrades this one check to a warning: record it and carry `component_contract_warnings[]` in the handback rather than failing. An exception row with no reason is a **FAIL**, not a pass;
   - **mechanical sweep** — one Grep pass over everything authored this run (`src/components/**` files in any manifest's `files_written`/`components_widened`, plus every route under `src/app/<name_slug>/**`). Each pattern below is a **FAIL** on any hit; these are mechanical, not judgement calls. The **Owner** column names the canonical source of the rule, because the sweep now enforces two floors: the visual/tactile one (`visual-craft-standard.md`) and the component contracts (`design-system-standards.md §1`, projected in `ux-baseline-checklist.md`). Judgement-dependent §1 items — verb-led labels, one primary per surface, validation timing, tooltip-on-truncate — are **deliberately absent**: the sweep's whole value is that every pattern in it is decidable by grep, and diluting it with false positives is how a gate stops being trusted. Those stay sub-agent self-checks (`step-sub-render-surface.md` rule 5a).
     | # | Pattern | Owner | Why it fails |
     |---|---|---|---|
     | 1 | `\b(?:bg\|text\|border\|ring\|from\|via\|to\|divide\|outline\|decoration\|shadow)-(?:white\|black\|slate\|gray\|zinc\|neutral\|stone\|red\|orange\|amber\|yellow\|lime\|green\|emerald\|teal\|cyan\|sky\|blue\|indigo\|violet\|purple\|fuchsia\|pink\|rose)(?:-\d{2,3})?\b` | craft | Tailwind palette colours do not flip with the colour mode (`shared-component-conventions.md §4a`) |
     | 2 | `#[0-9a-fA-F]{3,8}\|rgb\(\|hsl\(` inside `className`/`style` | craft | raw colour literal — same failure, different disguise |
     | 3 | `duration-\d\|duration-\[\d+m?s\]\|shadow-\[\|text-\[\d\|rounded-\[\d\|ease-linear` | craft | hardcoded craft literal; timing/elevation/type/radius are tokens (`visual-craft-standard.md §1`) |
     | 4 | `duration-(?:fast\|base\|slow)\b` as a class name | craft | emits **no CSS** — `--duration-*` is not a Tailwind namespace, so this fails silently. Correct: bare `transition`, or `duration-[var(--duration-base)]` |
     | 5 | `from ['"]framer-motion['"]` | craft | JS motion survives the contrast sweep's transition kill, making that gate pass on a broken colour mode (`visual-craft-standard.md §9`) |
     | 6 | `['">](?:✓\|✔\|✕\|✗\|ℹ\|⚠\|●\|•)` as rendered content | craft | text-glyph icon: ignores stroke weight and the type ramp, differs per platform. Use `lucide-react` |
     | 7 | `onClick` on a `div`/`span`/`li` **without** `data-pressable`, or on a non-table `tr` without `data-pressable`/`data-clickable` | craft | the global press layer cannot match it, so the element is silently untactile (`visual-craft-standard.md §2`) |
     | 8 | `onClick` (or `data-clickable`/`data-pressable`) on a `<tr`/`<TableRow` inside a **data table** | **§1** | whole-row click is forbidden outright — **no attribute redeems it**. The identifier becomes a link/button in its own cell; row actions go in a dedicated action column (`design-system-standards.md §1 > Tables`) |

     Pattern 1 is the one with a shipped precedent: a real run's `StatusBadge` used `border-green-300 bg-green-100 text-green-900` and its notice banner used red/green pairs — 15 hits total, past lint, typecheck, the per-route smoke **and** the both-modes contrast sweep, because that sweep only measures the states it happens to render. A grep catches what a renderer cannot.
   - **responsive coverage** — when `device_targets.breakpoints` is anything other than `["desktop"]`: at least one `sm:`/`md:`/`lg:` utility appears in **each** authored route and in **each** new layout-bearing component; no authored table uses `overflow-x-auto` as a substitute for the `GR-18` card collapse. Zero breakpoints across a run that declared a narrow target means the contract was read and not applied — the last real run authored zero breakpoints in every generated file. Also confirm each `components_widened` entry still typechecks and has no forked sibling (`*Mobile`, a markup-duplicating `variant`) beside it;
   - the verify gate returned `pass` / `pass-with-warning`.
2. Hand back to the orchestrator:
   - **`ok {name_slug, route, components_created[], components_reused[], components_widened[], device_targets, component_contract_warnings?, smoke_skipped?}`** — the orchestrator advances to the landing update (Step F4). `component_contract_warnings[]` carries every §1 check downgraded by a design-spec §9 `Exceptions` row (`{surface, item, reason}`); it is present only when non-empty, and the orchestrator surfaces it in the Step-G accept summary so a recorded exception is visible to the consultant rather than silently absorbed. `device_targets` is echoed because the landing-updater renders it as a badge on the prototype's card and records it in `.registry.json`; when it was defaulted (a spec predating the field), say so in the handback rather than presenting the default as a choice.
   - **`failed {structured}`** — a self-validation miss that bounded retry could not clear, or an `RF-12` halt. The orchestrator does not update the landing; the broken route + spec remain on disk for inspection.
3. Do not present to the consultant or run an accept loop — the orchestrator owns the Step-G accept gate.
